# 来源规则

电力题的事实只来自附件里的连续原文。

## 可以当附件

- 作者自己的电力材料：操作票、工作票、缺陷单、验收清单、保护信息、运行日志。脱敏后放进 `attachments/`。原始内部件不进包。
- 政府公开页：国家能源局及派出机构网站。抓取当日用浏览器或 `curl` 保存正文，台账记录 URL 和日期。
- 作者手头的正版标准摘录：只摘本题要用的条，并注明版本。没有书或正式文本，就不引条款号。

## 不能当附件

- 搜索结果摘要、百科、培训网站转载的标准表。
- 模型生成的「某站缺陷单」。
- 只记得结论、找不到原句的个人经历。没有单据，就不能把某次缺陷或工程写成题。

## 公开通报怎么出才算工作案例

业务背景写成班组要完成的电力工作：反事故学习核对、月报电气条目摘录、票面与公开条款对照。输入是通报或票面。交付是核对表。评价依据是原句在不在附件里。

不写成「请分析这次事故的根因」。根因多数不在公开段落里，模型会补调查结论。

`author_on_scene` 默认 `否`。作者后来确认自己在场，并拿出当时单据，才改成 `是`，并且附件改用单据，不用新闻稿代替。

## 抓取

抓取时使用你自己的网络环境，不要把代理地址、账号或命令历史写进仓库。抓到的 HTML 去掉脚本、导航、联系人电话和邮箱后再存。台账写明删了哪一段。页脚电话留在附件里会让自检失败，也会把无关个人信息带进题包。
